# 匿名參考程式：jade-lynx-c0ee（PA1）

依 [最新版 V2 題面及零元補充案例](../../README.md)修復原始參考程式。`original/` 是已知有誤的歷史版本，僅供比較；`fixed/` 是修復後重新驗證的版本。原始檔內沒有姓名、學號或本機路徑，因此歷史版本只改成通用檔名，原始位元組與編碼保留。每份程式各有自己的 `main()`，分別編譯。

| 版本 | 已知原版問題 | 修復及驗證 |
|---|---|---|
| [原版一般版](original/basic.cpp) / [修復一般版](fixed/basic.cpp) | 第一次迴圈讀取未初始化 `price[0]`；拒絕最新版允許的價格 0；讀取失败會持續重讀，浮點價格轉整數有超範圍風險。 | 初始化價格、接受 0、零元直接不選券、整數計算 90%／80%／72% 並最後截尾；保留原本函式分工及組合枚舉付款方法。306 組完整輸出比對通過（含 `-O0`、`-O2`）。另以獨立可達金額模型核對 1,331 個錢包／價格組合，每種最佳化各跑一次，共 2,662 組通過。 |
| [原版找零擴充版](original/return_change.cpp) / [修復找零擴充版](fixed/return_change.cpp) | 同樣讀取未初始化價格、拒絕 0，讀取失敗與超大價格沒有安全結束／拒絕處理。 | 同樣修復價格與折扣，保留原組合枚舉、找零顯示及庫存更新。328 組有狀態交易檢查通過（含兩種最佳化），逐筆驗證實際付款未超過持券、折扣值正確、淨庫存減少等於應付金額、零元不動庫存，且不漏處理交易。 |

找零擴充是原參考程式自行增加的功能：付款後會收到 `Change is as follows:` 列出的券。因此它的庫存可以和無找零一般版不同；沒有把它強改成「最少損失」程式。兩版均補上讀取失敗／EOF 結束處理，價格改以逐 token 的整數範圍檢查，避免超大輸入造成浮點轉整數未定義行為。

在儲存庫根目錄重跑：

```sh
python tests/test_repaired_pa1_pa2.py
python tests/test_repaired_pa1_wallets.py --build-dir /tmp/pa1-wallet-check
```

可用 `--cxx` 指定編譯器，`--build-dir` 指定建置位置。Windows 使用 GCC 14.2.0，C++11、`-Wall -Wextra -Wpedantic -Wconversion -Werror`，分別編譯 `-O0` 和 `-O2`；僅執行檢閱後重新編譯的修復版，設逾時與輸出上限。測試原始版本並非本測試腳本的工作。
