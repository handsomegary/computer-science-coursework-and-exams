原版第 21／22／23 次提示會印成 `21th`／`22th`／`23th`。它先做 `int` 十進位加法及二進位轉換，再用來判斷範圍；輸入如 `8 2147483647 -1` 會先發生有號溢位或不可儲存的 0/1 十進位數字編碼，而非安全拒絕。保存十進位累加值也不符合最新版指定的二進位運算。

修復保留十進位欄位儲存 0/1 的方式，以及 `decimal_to_binary`、`binary_to_decimal`、`binary_adder` 三個遞迴函式。重新整理輸入／重讀迴圈與進位傳遞，先限制輸入可以編碼到 19 位，再用遞迴 XOR／AND 全加器計算；累計值來自二進位結果，不用十進位相加來預算結果。這些是為了滿足最新限制所需的控制流程重寫，不是把儲存庫主要解答整份替換進來。

沒有全域／static 變數，本地變數與函式參數只有 `int`／`long long int`，使用者輸入保存為 `int`，轉換後數字保存為 `long long int`。不使用陣列、字串或浮點數；非法 token 逐字消耗後重新提示，sentinel 在所有輸入位置都能結束。
