# 匿名參考程式：moss-lynx-5375（PA2）

依 [2021-11-14 最新題面](../../README.md)修復兩個版本。`original/` 保留已知有誤或不符合結構限制的歷史來源，僅供比較；`fixed/` 是修復後重新驗證的版本。原碼沒有姓名、學號或本機路徑，歷史來源只更改通用檔名，位元組完整保留。兩個版本需分別編譯。

| 版本 | 原版問題 | 修復與結果 |
|---|---|---|
| [原版一般版](original/basic.cpp) / [修復一般版](fixed/basic.cpp) | 使用 `long long` 保存十進位輸入，並以 `a += b` 保存累加值，違反最新版結構要求。遞迴處理第 19 位之後仍計算 `c * 10`，形成無法存入有號 `long long` 的 10¹⁹，即使最後結果仍在合法範圍也有未定義行為。 | 保留遞迴轉換、英文序數函式及 0/1 數字容器；輸入改存 `int`，累加只用有固定深度、明確進位的遞迴二進位全加器。298 組公開案例、邊界、輸入復原、序數及固定種子序列通過，含之前全部適用測試及 `-O0`／`-O2`。 |
| [原版加分版](original/signed.cpp) / [修復加分版](fixed/signed.cpp) | `8 -19 -11 0` 的第一個結果 −11 曾印成 `1100101`，正確為 `10101`。使用 `static` 輸入、非遞迴負數轉換、浮點 `log2`／`log10` 決策、十進位累加；零和分支及範圍也有問題。 | 保留二補數及遞迴位元容器設計，重寫負數編碼、符號延伸與控制流程；低 19 位容器加獨立符號位，避免儲存 20 位容器。預設最短二補數模式 366 組通過；課程範例寬度相容模式另 366 組通過，兩種模式均含之前全部適用測試及 `-O0`／`-O2`。 |

兩個修復版本均沒有全域或 `static` 變數，所有本地變數／參數僅 `int`／`long long int`；十進位輸入保存為 `int`，二進位數字容器保存為 `long long int`。轉換、加法與回轉換均使用遞迴，不以十進位加減預算結果。較大的重寫是為了修復原版不一致的正負數分支及符合最新結構限制，保留的是原遞迴與數字容器方法。

最新版要求負數使用「最少位數」，但公開範例的 −1=`11`、−4=`1100` 與這句要求矛盾。本修復的預設採真正最短二補數：−1=`1`、−4=`100`、−8=`1000`，因此可存的負數下界為 −262144；正數仍加前置符號位 0，零結果顯示 `00`。相容模式使用原範例的「絕對值位數再加一個符號位」規則，負數下界為 −262143。相容選項是編譯期巨集，不引入 `char**` 參數而違反資料型態限制；兩種模式的算術結果相同。

```sh
g++ -std=c++11 -Wall -Wextra -Wpedantic -Wconversion -Werror fixed/basic.cpp -o pa2_basic
g++ -std=c++11 -Wall -Wextra -Wpedantic -Wconversion -Werror fixed/signed.cpp -o pa2_signed
g++ -std=c++11 -DCOURSE_WIDTH=1 fixed/signed.cpp -o pa2_signed_course_width
# 在儲存庫根目錄：
python tests/test_repaired_pa1_pa2.py
python tests/test_repaired_pa1_pa2.py --course-width --only-signed
```

測試使用獨立 Python 整數模型與真正最短二補數模型，比對完整輸出並忽略空白差異；包含兩組公開加分案例的正確算術、混合正負數、零和後繼續計算、所有負二次方、19 位邊界、溢位後保留前次部分和、非法 token 與多次序數。GCC 14.2.0、C++11，`-Wall -Wextra -Wpedantic -Wconversion -Werror`。歷史程式有溢位／錯誤結果風險，測試腳本只執行重新編譯並檢閱後的修復版本，有執行逾時及輸出上限。
